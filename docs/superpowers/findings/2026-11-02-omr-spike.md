# OMR spike findings (Phase 0)

Date: 2026-11-02. Machine: WSL2, Ubuntu 24.04, Python 3.13.9, music21 10.5.2.

## Verdict: GO with Audiveris

Notes, rhythms and slurs came through well on all three sheets. The failures are in structure and markings, not pitches, except one phantom key signature (below). No need to try homr/oemer yet.

## Install (user-level, no sudo)

- Audiveris 5.11.0: `Audiveris-5.11.0-ubuntu24.04-x86_64.deb` from the GitHub release, unpacked with `dpkg -x` into `~/.local/opt/audiveris`. Executable: `~/.local/opt/audiveris/opt/audiveris/bin/Audiveris`. **Capital A**: CLAUDE.md's `audiveris` is wrong on Linux. Bundled Java runtime works; no system Java needed.
- MuseScore Studio 4.7.6 AppImage in `~/.local/opt/musescore/MuseScore.AppImage`. Headless works with `QT_QPA_PLATFORM=offscreen <AppImage> --appimage-extract-and-run -o out.png in.mxl` (PNG gets a `-1` page suffix). No FUSE or display needed.
- `pdftoppm` and `pdfinfo` are not installed; PyMuPDF used for page images (scratch venv only).

## Audiveris behaviour

- Command `Audiveris -batch -export -output <dir> -- <pdf>` works as in CLAUDE.md. Exit code 0, about 11 s per one-page sheet.
- The output dir gets `<stem>.mxl`, `<stem>.omr` and a timestamped `.log`. Only `.mxl` is the result. No multi-movement files in these three.
- Exit 0 even with warnings. "No installed OCR languages" / "Missing support for 'eng'": tesseract data is absent, so title, tempo and composer text are not read. Not blocking.
- OMR names the part `Voice`, instrument "Voice Oohs", no transposition. Source instrument cannot come from the file (confirms spec C4).

## Interval check (spec C6): confirmed

music21: written alto C4 +P4 → tenor F4, and both sound E♭3. Verified for C4, D4, E4, F♯4, B♭3, A5. Alto→tenor is a written P4 up; tenor→alto P4 down.

## What this means for the plan

- **Duration check alone is not enough.** All three show 0 mismatched measures yet contain real errors. Phase 2 must also flag: key-signature changes (especially ones that return to the original), voltas/repeats that look invented, and bar-count differences when multi-measure rests are present.
- The phantom key signature is the dangerous case: it silently changes pitches, and any transposition carries it forward.
- Task 3: search for `Audiveris` (capital A) as well as `audiveris`; add `~/.local/opt/audiveris/opt/audiveris/bin` and `/opt/audiveris/bin` to known dirs.
- Task 5: filter results to `*.mxl` only; `.omr` and `.log` share the directory.
- Playback/transposition of Amazing Grace would work on pitches but its bar count is wrong, so re-engraved output will not match the original numbering.

## Not done / limits

- The by-eye comparison used low-resolution renders; subtle accidentals or ties could be missed. A measure-by-measure ground truth (for example the original scores in MusicXML) would give real numbers.
- No tesseract language data installed; installing it would likely restore title and tempo text.
